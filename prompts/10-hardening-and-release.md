# PROMPT 10 — Production hardening, usability, security, deployment and final P0 release gate

Read rules and approved acceptance/traceability; perform an **independent gap audit**, fix P0 defects and prepare demo/release. Do not claim production readiness by analogy to a local prototype.

1. Walk every P0 acceptance criterion in a real seeded end-to-end run: instructor sign-in → calendar/ICS + material import → one roadmap review/approve → group graph + session details + benchmarks → transcript evidence review → post-session draft approval → grounded assistant Q&A → dashboard reminders → audit history. Save screenshots/logs or reproduction steps only where permitted and ensure they come from actual running app.
2. Verify functional/NFR/UX: unit, integration, e2e, permission & IDOR, concurrency/approval replay, migrations and rollback plan, recovery after worker crashes, idempotent sync, invalid/corrupt uploads, package export, accessibility keyboard + graph list, responsive layouts, loading/empty/error states, cross-browser critical paths, real usability script outcomes (mark if untested).
3. Security checklist: dependency scans, credential leaks, OAuth scope and revocation, encrypted tokens where applicable, PII/transcript consent and retention, CORS/CSRF, tenant isolation, sanitization/XSS, SSRF/upload decompression and path traversal, file access controls, LLM prompt injection, auth error information leaks, rate limits. Never run destructive scans against production without authorization.
4. NFR measurements on recorded representative fixtures: import throughput, graph rendering, API p95, agent latency and token cost, queue retry behavior; provide actual numbers and hardware/context, no invented performance guarantees.
5. Deployment: reproducible local setup + approved hosted deployment instructions, migrations/seed, backup/restore, structured logs/metrics, health checks, HTTPS/secrets handling, minimal monitoring, CI release gate and rollback/runbook. If cloud hosting isn't approved, do not deploy; provide operator-ready steps.
6. Documentation: README quickstart, architecture/ERD/API examples, admin operations, trouble-shooting, privacy/retention policy, limitations, manual, demo script, roadmap for deferred P1/P2. Ensure `docs/REQUIREMENTS_TRACEABILITY.md` has test references for all P0.
7. Classify every P0 criterion PASS / FAIL / NOT TESTED, with evidence. Produce `docs/RELEASE_READINESS.md`, `docs/TEST_REPORT.md`, `docs/SECURITY_REVIEW.md`, `docs/KNOWN_LIMITATIONS.md`; clearly mark release **NO-GO** if a security-critical or core flow fails. Fix high severity issues, rerun relevant tests.

**FINAL GATE R1:** Show exact P0 demo status, unresolved blockers, whether deployable, and ask user for release acceptance. Do not start P1 until approved.
